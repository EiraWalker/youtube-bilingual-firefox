# 按播放位置翻译与手动字幕缓存

日期：2026-10-15。类型：待实施规格。测试范围：用户已确认。

## Problem Statement

用户只打开视频观看片刻，也可能因为已经开启双语字幕而触发全片字幕翻译。当前分段翻译只优化请求大小和播放位置优先级，译文缓冲充足后仍继续提交后续字幕，暂停、切换视频或关闭双语显示也不停止后台新增请求，产生无用的接口调用。

当前译文默认持久保存到扩展内部，用户没有明确选择是否缓存，也不能通过自行配置的文件夹直接获取可用字幕文件。用户需要把本次观看的临时译文与明确保存、以后复用的字幕缓存区分开。

## Solution

双语字幕仅按当前播放位置推进，在有限的前方范围内分段翻译；缓冲充足就停止提交，继续播放并消耗缓冲后才补充。暂停、离开视频或关闭双语字幕后停止新增请求，已发出的请求允许返回，已有译文保留。

默认仅在内存中保留本次观看的字幕与译文，不自动写入持久字幕库或下载字幕文件。在播放器“双语字幕”按钮旁添加“缓存字幕”按钮。用户点击后，把当前可用字幕及已有译文保存到配置的缓存文件夹；再次观看时复用匹配的缓存，只翻译当前范围内缺失的内容。

配置菜单提供缓存文件夹路径，用户能在该位置找到可读取的字幕文件。缓存操作不启动全片翻译；未完成的译文可以作为部分缓存保存。

## User Stories

1. 作为只想短暂观看视频的用户，我希望仅翻译当前播放位置附近的字幕，以便避免为未观看内容消耗接口额度。
2. 作为观看视频的用户，我希望提前准备有限范围的译文，以便播放时能及时看到双语字幕。
3. 作为用户，我希望缓冲充足后自动停止新增请求，以便扩展不会悄悄翻译全片。
4. 作为用户，我希望继续播放消耗缓冲后再补充译文，以便无需反复手动启动翻译。
5. 作为暂停视频的用户，我希望暂停期间停止新增请求，以便暂停时间不会扩大翻译范围。
6. 作为用户，我希望恢复播放后复用已有译文，以便不重复翻译相同字幕。
7. 作为切换到另一视频的用户，我希望旧视频停止新增请求，以便只为当前观看内容准备译文。
8. 作为关闭视频标签页的用户，我希望旧任务停止新增请求，以便不留下持续运行的全片翻译任务。
9. 作为切换到其他标签页的用户，我希望离开的隐藏视频页停止新增请求，以便后台视频不会继续扩大翻译范围。
10. 作为关闭双语字幕的用户，我希望关闭显示同时停止新增翻译请求，以便按钮行为与资源消耗一致。
11. 作为用户，我希望已提交的请求仍能正常返回并保留结果，以便不浪费已经发生的调用。
12. 作为跳转播放位置的用户，我希望下一批请求优先服务新位置，以便快速获得当前内容的译文。
13. 作为用户，我希望跳转后不再补译已跳过且不在当前范围内的字幕，以便不会变相恢复全片翻译。
14. 作为调整倍速的用户，我希望预取适应播放节奏且仍受明确范围约束，以便兼顾及时显示和可控消耗。
15. 作为用户，我希望译文暂未就绪时继续播放并显示原字幕，以便不中断观看。
16. 作为用户，我希望默认不持久缓存或下载字幕，以便只有主动选择的内容才保存在磁盘上。
17. 作为用户，我希望暂停后仍能使用本次观看已有译文，以便临时保留不依赖磁盘缓存。
18. 作为用户，我希望在“双语字幕”旁直接看到“缓存字幕”按钮，以便随时保存当前可用字幕。
19. 作为用户，我希望无需等待全片翻译也能缓存已有译文，以便保存当前已看的内容。
20. 作为用户，我希望缓存操作不会自动补译全片，以便保存文件不额外产生翻译费用。
21. 作为用户，我希望明确知道缓存是部分完成还是全部完成，以便理解文件覆盖范围。
22. 作为用户，我希望可再次点击缓存来更新已有结果，以便将后来获得的译文纳入缓存。
23. 作为用户，我希望后续观看能自动复用匹配的缓存，以便减少等待和重复调用。
24. 作为用户，我希望部分缓存只在当前观看范围缺少译文时才补译，以便不会为了补齐缓存处理全片。
25. 作为用户，我希望浏览器重启后主动缓存仍然可复用，以便缓存不依赖上次会话的内存。
26. 作为用户，我希望设置缓存文件夹路径，以便把字幕保存在自己管理的位置。
27. 作为用户，我希望设置页面显示实际缓存目录并可定位文件夹，以便直接取得下载缓存的字幕。
28. 作为用户，我希望文件夹内有通用字幕文件，以便在扩展以外阅读和使用。
29. 作为用户，我希望目录不可写或保存失败时保留已有缓存和临时译文，以便重试时不丢失内容。
30. 作为用户，我希望更改目录后新缓存写入新位置，以便不会暗中移动或删除旧文件。
31. 作为用户，我希望不同视频、字幕轨道和翻译配置的缓存不会混用，以便获得正确的译文。
32. 作为同时打开多个视频页的用户，我希望任务按各页面实际播放状态控制，以便不会相互恢复已停止的任务。
33. 作为已有版本的用户，我希望旧版保存的字幕继续可读，以便升级不会丢失原有译文。
34. 作为用户，我希望缓存文件不包含接口密钥，以便可以自行管理和分享字幕文件。
35. 作为未安装缓存组件的用户，我希望仍可正常使用临时双语字幕，以便缓存文件功能不阻断观看。

## Implementation Decisions

以下为本规格拟实施的决策，尚未改变当前产品行为。用户未指定的数值和文件组织方式采用下述实现默认值。

### 1. 按需调度及有限范围

- 保留整轨获取源字幕时间轴的能力；获取时间轴不等于授权整轨翻译或持久保存。
- 修改现有后台字幕任务服务及播放器消息协议，由有效观看需求决定是否允许提交请求。普通观看不再以整轨完成为任务目标。
- 有效观看需求定义为：视频页可见、该视频正在播放、双语字幕开启、字幕轨道匹配且不在广告期间。单纯失去窗口焦点不视为离开视频；标签页隐藏、导航离开、切换视频、关闭页面、暂停、播放结束或关闭双语字幕均撤销相应页面需求。
- 默认预取上限为当前播放位置向后 120 个源视频秒；连续可用译文缓冲低于 60 个源视频秒时补充，达到上限后停止提交。数值集中定义，后续可按测量调整；本期不增加缓冲参数设置界面。
- 以字幕条目为不可分割单位；只选择与当前播放位置及前方窗口相交的条目。跨窗口边界的单条字幕允许保持完整，但不因此纳入下一个窗口外条目。当前字幕缺失时应立即具备请求资格。
- 使用尚未翻译且未被在途片段占用的条目规划请求；规划时同时约束所有待提交片段的总范围，不能每个并发槽各自向后扩张一个窗口。
- 倍速参与补充时机和请求大小计算，但不能扩大 120 个源视频秒的范围上限。字幕空白按已知时间轴计算，不得为填满请求而跨越远处空白选取窗口外字幕。
- 缓冲充足只进入等待补充状态；不得为了填满并发槽继续发送，也不得回绕补译播放位置之前的未观看缺口。
- 保留每视频最多三个实际在途请求的上限；这是并发上限，不是必须填满的配额。不同视频分别受各自有效观看需求和有限窗口约束。
- 正常页面事件应立即通知后台撤销需求；后台在每次提交及自动重试前重新检查资格。页面异常消失时，以页面生命周期监听及有限期存活信号清理失效需求，不能无限保留最后播放位置继续提交。
- 同一视频有多个页面时分别维护需求；只有仍存在有效观看需求才可继续，单个页面的暂停不能清除另一正在观看页面的需求。所有请求仍须属于某个有效需求的有限窗口。
- 暂停、离开和跳转不强制取消已经发出的远程请求。结果通过校验后合并到内存，但其返回不得自行恢复已失效的需求或触发下一批请求。
- 已排队内容、等待重试的内容同样受新资格检查约束；暂停期间不发送自动重试，恢复后只重试仍在有效窗口内的缺失内容。
- 跳转只更新后续请求范围；旧在途结果可以接收，未发送的旧位置片段不继续执行。前后跳转均复用已存在的译文。
- 用户点击“取消翻译”仍可执行明确取消；配置库中的恢复入口不得绕过观看资格启动全片后台翻译。

### 2. 临时译文与主动缓存

- 播放器显示依赖内存中的已校验条目，不再要求译文先写入持久存储才能公开。原有并发合并、版本识别及条目校验仍需保留。
- 默认观看不把新获取的源字幕、译文、部分任务或恢复记录写入扩展持久存储，也不创建字幕文件；配置项仍可正常持久保存。
- 暂停、关闭显示、离开视频及普通页面导航不会立即清空本次浏览器会话的临时译文，返回同一视频可复用。浏览器退出后这些未主动缓存的译文不保证保留。
- 在播放器“双语字幕”按钮旁添加独立“缓存字幕”按钮，沿用播放器原有视觉和键盘可访问性。尚无源字幕时禁用；可用原字幕但暂无译文时允许缓存原字幕及零译文状态。
- 一次点击保存当时已有的字幕及译文快照，支持部分缓存；不会开启双语字幕、恢复暂停任务、补译剩余字幕或启用之后自动落盘。需要更新时再次点击。
- 保存进行中防止重复提交；保存完成状态必须以文件实际写入成功为准。提供必要的“缓存中”“已缓存”“部分缓存”或失败状态及条目数量，不堆叠解释性文案。
- 后续结果到达只更新内存；未再次点击缓存时不能把新增条目误报为已经持久保存。
- 对同一缓存身份再次缓存时合并已有有效条目，避免较旧或更少条目的快照覆盖较完整缓存；文件按稳定身份更新，不持续制造重复下载副本。

### 3. 文件格式与译文复用

- 每个缓存包含版本化的结构数据及通用 SRT。结构数据保存视频身份、源字幕轨道、源时间轴及内容指纹、目标语言、翻译服务与模型配置指纹、已有译文、修订信息和完成度，不保存 API Key 或其他认证信息。
- 通用文件至少提供完整已获取源轨道的原文 SRT，以及仅含已有译文条目的双语 SRT；没有译文时不生成空的双语文件。部分双语文件明确标识部分完成，不能以原文冒充译文或编造缺失条目。
- 全部字幕条目已有有效译文时才可标记整轨缓存完成；部分缓存始终暴露真实已翻译条目数和总条目数。
- 使用视频身份和缓存身份生成稳定且适合本机文件系统的名称，标题仅作可读部分。保存采用完整修订发布方式，防止中途失败损坏之前可用版本。
- 再次开启双语字幕时，通过当前配置目录查找匹配缓存、校验格式及源字幕一致性，将匹配条目加载到内存后显示；缓存读取本身不触发翻译请求。
- 部分缓存只为当前有效观看窗口补缺；不会为了把部分缓存变成完整缓存而执行整轨翻译。
- 文件夹中的结构缓存是跨浏览器会话复用的来源；只导出一个 SRT、却仍完全依赖扩展内部字幕库，不满足本需求。重启后应能直接读取文件夹内缓存。
- 既有 SRT 导出入口保留为用户主动操作；普通显示不能隐式调用下载。旧版内部缓存保持可读，不自动删除、导出或迁移；新获取内容遵循手动缓存策略。

### 4. 缓存目录和本地文件能力

- 配置菜单新增缓存文件夹路径及目录定位动作，显示实际生效的绝对位置。目录未配置时点击缓存进入目录设置，不静默写入未知位置。
- 保留用户要求的本地自定义文件夹路径，而不是仅提供浏览器下载目录内的相对子目录。Firefox 的下载接口不能直接写入任意绝对目录，也不能作为读取该目录中缓存数据的通用接口。
- 为实现自定义目录写入及后续回读，本期缓存功能采用 Windows 本地 Native Messaging 文件访问组件，包含配套安装、注册、卸载说明与交付物；该组件只承担缓存目录及字幕文件操作。
- 缓存组件缺失、未连接或目录不可读写时，普通临时双语字幕仍可运行；设置或缓存操作给出简短且可执行的状态，不能声称已经保存。
- 本地组件只接受扩展后台对已配置目录的缓存读写和定位请求，不向网页开放任意文件读写或命令执行能力；对文件名与最终路径进行约束，防止字幕标题改变目标目录。
- 结构数据较大时采用受限消息分块或文件引用协议，并验证完整性，避免长视频缓存超过本地通信单条消息限制。具体协议由实现确定，不能以截断数据完成缓存。
- 保存路径前验证目录可用性；取消配置或验证失败时保留之前有效设置。更改路径只影响之后查找及写入位置，不自动扫描整个磁盘、移动或删除旧目录文件。
- 文件夹打开或定位动作仅由用户点击触发；用户可直接从配置展示的位置获取缓存字幕。

### 5. 状态和架构文档

- 以观看需求状态、翻译进度、缓存快照修订三个维度表达行为；“缓冲够用”“已暂停”“部分缓存”和“整轨已完成”不可混为同一个完成状态。
- 播放器负责上报视频身份、页面会话、播放位置、倍速、暂停与可见性等观看状态；后台负责统一资格检查、并发限制、缓存身份和请求提交；文件组件负责受限目录操作。
- 扩展持久存储可保存设置、非字幕内容的缓存索引与旧版记录；新字幕持久内容以用户主动缓存的文件为准，索引丢失后仍能通过配置目录恢复。
- 实施时追加新的 ADR，明确取代旧决策中的后台持续补译、默认持久保存和持久化后才公开译文；保留分段翻译、整轨源获取、在途请求可完成、原字幕回退及缓存身份校验等仍适用决策。
- 实施时补充领域术语，明确临时译文、观看需求、预取窗口和主动缓存快照，沿用字幕条目、字幕翻译段、译文缓冲及译文复用等既有术语。

## Testing Decisions

测试范围已由用户确认：复用现有后台服务入口验证翻译请求范围与停止时机，补充“缓存字幕”按钮、目录配置、重启后复用和真实文件回读验收。

- 主要测试接口采用现有后台字幕任务服务的公开操作，并通过扩展消息入口验证页面到后台的契约。沿用可注入翻译请求、存储及可控响应的测试方式，尽量集中覆盖完整外部行为；不为了测试新增另一套调度器。
- 好的测试观察实际发送的字幕条目、请求数、显示结果、持久存储内容及真实文件，不断言私有方法调用次数、内部队列形状或特定实现步骤。
- 以长视频在固定位置持续等待的用例证明：所有请求均在有限窗口内；即使依次释放所有远程响应且持续等待，后续请求数也不会增长到整轨完成。多个并发请求合计仍不得超出窗口。
- 验证播放消耗缓冲才补充、倍速不扩大硬上限、字幕空白不带来远处请求、跨界单条字幕保持完整，以及视频尾部不回绕补译之前缺口。
- 在请求正在执行、待重试、准备合并结果等不同时间点暂停、隐藏页面、关闭显示、切换视频或关闭标签页，验证不新增请求；释放旧响应后确认已有译文保留且不会自动继续。
- 验证恢复播放及前后跳转只请求当前窗口缺失条目；同视频多页、不同视频、失效会话、旧位置上报及异常页面失联不会泄漏观看需求或突破并发限制。
- 默认观看后检查持久存储和文件系统：新源字幕、译文及恢复任务均未落盘；设置及旧版缓存不被误删。浏览器会话内返回能复用内存，重启不会恢复未缓存字幕或自行调用接口。
- 沿用现有播放器 UI 测试及 Firefox 隔离集成环境，验证“缓存字幕”位置、键盘操作、禁用条件、保存状态，以及点击缓存不改变播放状态或增加翻译请求。
- 沿用现有设置页测试验证目录保存、有效路径展示、失效路径和缓存组件未安装等用户可见结果；目录定位只响应明确点击。
- 通过后台缓存操作和真实本地组件在临时目录完成写入、逐项回读和字幕解析；测试中文及空格目录、文件名冲突、重复更新、写入失败、断连、损坏结构文件和大缓存分块。测试不得写入或清理用户真实缓存目录。
- 冷启动新的后台实例并清空新版本的字幕索引后，仅通过配置目录加载已缓存文件，验证匹配译文可直接使用、部分缓存只在有效窗口补缺、未匹配配置不混用。
- 验证保存快照与在途返回交错不会把未落盘数据标为已缓存；重复缓存不丢已有条目，失败不破坏前一有效版本，源时间轴与 SRT 时间戳保持一致。
- 验证旧版完整及部分缓存仍可读，但其恢复操作受新观看资格限制；配置变化、缓存文件删除或损坏不触发全片重译。
- 外部验收包含一次真实 Firefox 中的短时观看、暂停、离开、手动缓存、重启及目录复用流程，结合受控翻译服务请求记录和磁盘文件证明结果；模拟 UI 和单元测试不能单独证明真实文件夹落盘成功。
- 实施完成后运行现有测试套件、扩展构建与打包校验；按新规格更新旧的全片后台完成和默认持久化断言，不删除仍适用的安全、解析及字幕显示回归覆盖。

## Out of Scope

- 本次工作只编写并发布规格，不实现功能、不安装本地组件、不发布新版扩展。
- 自动翻译全片、点击缓存后后台补齐全片、暂停或离开后继续提交新的翻译请求。
- 自动下载视频、语音转写、无字幕视频识别或新增视频平台支持。
- 云端同步、跨设备缓存共享、字幕编辑器、批量缓存及自动扫描未配置磁盘目录。
- 本期不支持 macOS/Linux 本地缓存组件，不迁移浏览器扩展清单版本，也不修改 Firefox 全局下载目录。
- 自动迁移、移动或删除用户已有字幕文件和旧版缓存。

## Further Notes

- “有限范围”采用 120 秒上限、60 秒补充阈值，是本规格选定的实现默认值，并非用户指定数值；不影响必须存在明确硬上限的要求。
- “缓存字幕”按当前可用结果的手动快照处理，不代表用户授权新增全片翻译，也不默认开启持续磁盘更新。这是本次需求的范围解释。
- “保留已有译文”默认指本次浏览器会话内保留；只有用户明确缓存后，才承诺重启后的持久复用。
- 当前实现的主要差异已通过现有源码确认：调度没有缓冲停止门槛、页面离开只解除视图关联、译文默认写入扩展存储。现有测试结果不是新行为已经实现的证据。
- 自定义绝对目录及目录回读需要新增本地能力；仅保存文件名设置或提供另存为窗口不能满足配置目录后直接复用的完整验收。
- 技术依据：[Firefox downloads.download](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/downloads/download) 规定文件名路径相对浏览器下载目录，绝对路径会报错；[Firefox Native messaging](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/Native_messaging) 描述扩展与单独安装的本地应用通信方式。
- 测试范围已确认；具体缓冲默认值、手动快照语义及 Windows 本地缓存组件为规格中的拟实施决策，发布为 ready-for-agent 不代表代码已完成或组件已安装。
