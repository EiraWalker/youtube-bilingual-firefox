# 0.4.0 按需翻译与手动缓存验证

日期：2026-10-15。对应 Issue #7。功能实现、测试及本地打包已通过；本页不代表已安装到用户日常使用的 Firefox。

## 已实现行为

- 有效观看时只提交当前位置至前方 120 个源视频秒相交的字幕条目，缓冲低于 60 秒时补充；不回绕补译已跳过内容。
- 暂停、隐藏、离开、结束、广告及关闭显示撤销需求。已发请求允许返回，新增提交及重试均重新核对需求。
- 默认字幕和译文只保留内存，设置及旧版缓存兼容保留；新版本没有默认字幕落盘。
- 播放器相邻“缓存字幕”按钮保存当前快照，支持部分译文，不补译全片；之后的响应不自动更新文件。
- 配置本机缓存目录，经 Windows 本地组件写入结构缓存、原文与部分/完整双语 SRT，并在浏览器重启后直接回读。
- 随包提供组件安装、卸载脚本，使用当前用户注册，卸载保留字幕文件。

## Firefox 验收证据

命令：

```powershell
python -X utf8 scripts/test-firefox.py --report-tag demand-cache-040-final
```

测试使用生产构建，独立 headless Firefox 配置、本地 HTTPS YouTube 夹具、35 条字幕的合成视频及受控翻译 API。它操作实际播放器和设置页面，使用随附安装/卸载脚本注册真实 Native Messaging 宿主，并读取实际生成的文件。

已验证未开启/已开启但暂停时无翻译请求，播放缓冲就绪后停止提交，暂停跳转不发请求，恢复播放服务新位置。暂停或切到其他标签页时，放行被阻塞的在途响应，不会触发下一批；关闭双语显示后播放也不会新增请求。

普通观看后扩展存储只有设置，未创建字幕文件。配置中文缓存目录后手动保存得到 29 / 35 条译文的部分缓存，包含完整原文 SRT、部分双语 SRT 和结构文件。保存不改变暂停状态、不增加接口请求。

测试关闭整个 Firefox 会话，重启浏览器和扩展后台，保留的扩展存储只有设置，没有字幕索引。再次在暂停状态打开同一视频，仅从缓存目录恢复相同的 29 条译文，未增加翻译请求；再次缓存维持同一稳定身份目录。

本地完整报告：`output/firefox/demand-cache-040-final/report.json`，截图：同目录 `demand-player.png`。脱敏摘要见 [验收摘要](validation-evidence/demand-cache-0.4.json)。

## 产物与边界

- `dist/youtube-bilingual-firefox-0.4.0.zip`：临时加载/开发用 Firefox 扩展。
- `dist/youtube-bilingual-cache-windows-0.4.0.zip`：Windows 缓存组件源码、安装/卸载脚本及说明。
- 产物 SHA256 记录于验收摘要；GitHub Actions 重新打包时 ZIP 时间戳可能使文件散列不同。

本轮使用模拟翻译服务和本地 YouTube 夹具，不把结果扩展为真实公网 YouTube、真实付费 API 延迟、AMO 签名或无 Python 干净机器安装验证。已有真实 API 的旧版记录仅适用于对应旧版本。自定义缓存目录需要用户按说明安装组件，普通临时翻译不需要。

“打开缓存文件夹”的设置入口与后台权限通过消息测试，宿主目录路径已真实读写；本轮未启动 Explorer 窗口验收。
