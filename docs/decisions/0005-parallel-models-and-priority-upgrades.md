# 0005：多个启用模型并行竞速，按优先级升级时间轴译文

状态：已实现并通过代码与隔离浏览器回归；日常 Nightly 最终安装状态见 [0.5.0 验证记录](../validation-0.5.md)。

## 决策

一个字幕翻译段向每个启用的 OpenAI 兼容模型配置同时提交相同源条目。第一个通过完整编号及内容校验的候选立即成为择优译文，不等待所有模型。后续候选只有优先级严格高于已有择优译文时才能替换；数值越小越优先，同优先级先到先用。错误、漏译及无效响应不能覆盖可用结果。

择优发生在后台的字幕条目上，播放器仅按当前位置读取最新修订；正在显示的条目也可升级。时间轴不是破坏性出栈：跳回已观看位置仍可复用当前最佳译文；过期响应不会把更高优先级结果降级。只保留每条当前最佳文本及必要的内存优先级，不积累所有模型的全文副本。

用户明确选择把 ADR 0004 的并发口径由“最多三个实际请求”改为“最多三个在途字幕翻译段，每段并发所有启用模型”。因此最多同时有 `3 × 启用模型数` 个实际接口请求，所有启用模型可能产生费用。120 秒硬窗口、60 秒补充阈值、观看资格和暂停/离开后不追加请求的规则继续有效。各模型独立重试、独立计时和长度拒绝拆分；一个模型失败不能取消另一个模型或清除已可用译文。

旧单模型配置迁移为一个默认启用的模型配置。设置页拥有完整模型配置和所有启用地址的权限申请；YouTube 页面仅取得公共显示设置和必要的任务进度，不取得 API 凭证。多模型缓存身份覆盖启用集合、地址、模型、优先级和目标语言，避免改变配置后误用旧的择优结果；密钥轮换不改变缓存身份，单模型身份兼容原有缓存。

普通播放只更新内存缓冲。用户点击“缓存字幕”时保存当时的择优结果；此后到达的更高优先级译文仍只升级内存，需再次主动缓存才能写入文件。跨浏览器会话复用已保存的最佳快照，不仅为了升级已缓存条目的模型优先级而新增翻译。

## 取舍

选择“先可用、后升级”，而不是等待最高优先级模型或永久只取最快模型：既减少首次等待，也保留较慢但优先的模型带来的译文更新。代价是请求费用增加、字幕可能在显示期间更新，以及调度中必须分离字幕段槽位与模型请求的生命周期。

不采用真正的后进先出栈；视频播放依赖时间和字幕编号，用户跳转、并发乱序与较晚升级都要求可按时间轴反复读取。
