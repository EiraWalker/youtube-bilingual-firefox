# 整轨获取与完整翻译：已对齐需求

日期：2026-10-09。状态：已实现为 Firefox 0.2.0；最终验证记录见 [0.2.0 验收](validation-0.2.md)。

## 用户提出的方向

- 一次性获取整个视频的字幕，参考 yt-dlp 的字幕获取逻辑。
- 使用一条指令完成完整翻译，取代当前随播放位置分批翻译的形式。
- 本轮先讲述理解、对齐需求。
- 已确认的 Firefox、YouTube 播放器内双语字幕、OpenAI 兼容 API 继续作为讨论背景。
- 用户进一步确认：一个语言轨道；通常一次 API 请求完成，只有视频字幕文字实在太长时才例外。
- 用户确认仅在扩展中借鉴获取逻辑，不调用本地 yt-dlp 辅助程序。
- 用户同意翻译期间继续播放原字幕，状态显示“正在翻译”。
- 用户确认保存译文，并新增字幕导出功能。
- 用户确认仅导出 SRT，内容可选原文、译文或双语。
- 用户确认切换视频或关闭标签页后，已提交的翻译继续在后台完成并保存。

## 0.1.0 历史行为与术语澄清

0.1.0 的 API 请求已使用 `stream: false`。当时的增量行为来自任务调度：取播放位置附近约 75 秒内的待译字幕，每批最多 12 条。取不到时间轴时会翻译播放器当前字幕文本。0.2.0 已改为完整字幕任务，并取消该实时文本回退。

因此此次变化涉及字幕获取范围、翻译任务范围与请求次数；单纯关闭 API 流式返回不会改变现有行为。

已对齐的术语，整轨获取与整轨翻译已写入 CONTEXT.md：

- **整轨获取**：取得一个原字幕轨道覆盖整段视频的字幕时间轴。
- **整轨翻译**：以一个原字幕轨道的完整内容为翻译任务范围。
- **单请求翻译**：把完整待译内容交给一次 API 请求处理。

本轮已经明确：一个源语言轨道的完整时间轴；通常采用单请求翻译，过长字幕允许例外。具体长度判断属于实现时需验证的接口兼容细节，不在正常请求中提前拆分。

## 已对齐的流程

```text
用户启用双语字幕
→ 选择原字幕轨道
→ 获取完整字幕并保留条目编号和时间
→ 用完整原文提交翻译任务
→ 校验译文与原字幕逐条对应
→ 保存完整译文，按原时间轴在播放器内显示原文与译文
→ 可导出字幕文件
```

预期体验：翻译完成后，播放、暂停、倍速和任意跳转只读取已完成译文，无需因为播放位置变化再请求翻译。只有译文验证完整后才将任务标记为完成。

## 当前决策树

```text
完整字幕翻译模式
├─ 获取范围：一个源语言轨道的全片 [已确认]
├─ 翻译提交：通常一次 API 请求；文字实在太长时例外 [已确认]
│  └─ 过长判断与完整性校验 [实现时验证]
├─ 等待体验：继续播放原文，显示“正在翻译” [已确认]
├─ 获取架构：纯 Firefox 扩展，借鉴 yt-dlp 获取逻辑 [已确认]
├─ 译文复用：持久保存 [已确认]
│  └─ 复用匹配与清理规则 [实现建议见下文]
├─ 字幕导出 [新增、已确认]
│  ├─ 文件格式：仅 SRT [已确认]
│  └─ 内容：原文、译文、双语三种可选 [已确认]
└─ 离开页面时的翻译任务：后台继续完成并保存 [已确认]
```

导出保持源字幕时间轴。双语 SRT 的一个字幕条目中，原文在上、译文在下。译文或双语导出需要完整译文已通过校验；只有原文时可导出源字幕。

后台继续的范围是：Firefox 仍在运行时，页面切换或标签页关闭不取消已提交的整轨翻译。Firefox 退出后扩展不能继续运行；已完成、已保存的译文应在重启后继续可用。

缓存按视频、源轨道、源字幕内容、目标语言及翻译配置匹配；匹配则直接使用已保存的完整译文，提供重新翻译与清理入口。0.2.0 已增加完整结果的持久保存。

## 已知约束

- 完整输入和完整输出均受所用模型及兼容服务的长度、响应时限约束。API 为自定义服务，尚未验证其实际上限。
- 必须保留字幕条目编号和时间关系；模型只返回译文。输入完整不代表输出完整，需要校验缺失、重复编号和截断。
- 完整字幕读取失败时，实时文字回退不能满足“先获取全片”的要求。建议提示获取失败并提供重试，不将当前字幕文本误称为完整时间轴。
- Firefox 扩展不能直接启动任意本地可执行程序。使用真正的 yt-dlp 需要扩展之外的本地辅助程序及通信入口。
- 参考 yt-dlp 不代表一定能取得受限字幕，也不等于必须下载视频或音频。

## yt-dlp 参考事实

已通过 Context7 和官方文档、源码核对：yt-dlp 从播放器响应建立字幕轨道及格式列表，选择需要的轨道后下载整个字幕文件，其字幕获取不依赖视频当前播放位置。`--sub-langs all` 指全部可用语言，`--skip-download` 可以只取字幕而不下载视频。人工与自动生成字幕是源轨道的不同来源。

不能将元数据中列有字幕轨道等同于实际已下载成功。YouTube 字幕获取仍可能涉及客户端、PO Token、会话与站点限制；提供 cookies 本身不保证字幕可用。参考该逻辑不应承诺解决此前测试会话的空字幕问题。

使用实际 yt-dlp 与在扩展中借鉴提取逻辑是两个方案。前者需要另行安装本地辅助程序；Firefox 官方 Native Messaging 提供扩展与宿主通信方式。本机已通过路径检查确认存在 `D:\bin\yt-dlp.exe`，但本轮未运行下载或读取 cookies。
