# 文件与调用边界

本文描述 0.3.0 的分段翻译实现。完整源轨道仍一次获取，翻译与保存按片段增量推进。

```text
YouTube 请求 → page-bridge (MAIN world，轨道与完整字幕响应)
             → content (隔离环境，完整源轨道、播放位置、播放器视图)
             → background (权限、任务身份、每视频三个请求名额)
             → 用户 Chat Completions API
             → 片段校验 → 持久保存 → content 查询 → 当前 cue 双语显示

设置页 → 网站权限 / 扩展本地配置 → background
字幕库 → 任务进度 / 恢复缺失片段 / 取消 / 完整 SRT 导出
失败 → 后台控制台诊断 / 有限重试；页面保留中性状态和原字幕
```

## 模块责任

| 文件 | 责任 |
| --- | --- |
| `extension/manifest.json` | Firefox MV2 持久后台、网站与下载权限 |
| `src/content/page-bridge.js` | 原生字幕响应、完整轨道提取、同轨备用来源、字幕开关恢复 |
| `src/shared/captions.js` | 字幕解析、时间归一化、轨道选择、当前字幕查询 |
| `src/shared/buffered.js` | 连续片段规划、按倍速计算可用字幕缓冲 |
| `src/content/main.js` | 完整源轨道提交、播放位置上报、导航隔离、增量双语显示与恢复控件 |
| `src/background/translator.js` | Chat Completions 协议、严格编号校验、长度与错误分类、请求和响应体截止时间 |
| `src/background/main.js` | 消息来源校验、配置与权限、页面身份、SRT 下载 |
| `src/background/track-tasks.js` | 每视频并发调度、片段重试、任务去重、保存、恢复与完整性门槛 |
| `src/shared/srt.js` | 原文、译文、双语 SRT 序列化与安全文件名 |
| `src/shared/settings.js` | 配置验证、地址归一化、公开配置脱敏 |
| `src/ui/options.js` | 设置与权限、API 测试、任务进度、部分恢复与导出入口 |
| `scripts/build.mjs` | 打包可加载目录 |
| `scripts/test-firefox.py` | 独立 Firefox 生产包集成与公开页面回归 |

字幕和译文均用 `textContent` 显示。网页不能指定任意 API 请求地址；后台校验消息来自 YouTube 内容脚本或扩展页面，请求地址固定为用户保存的配置。API Key 只进入后台配置和认证请求，不进入任务公开状态、字幕缓存、SRT 或诊断日志。

## 调度与消息

`track:start` 接收一个完整源轨道及当前播放信息，按视频、源语言及人工/自动来源、源字幕内容与时间轴、目标语言、API 地址和模型建立任务身份。同身份的重复开启复用任务；新任务使用启动时的设置快照。部分缓存通过完整源轨道重新提交后核对身份再恢复，不能仅凭轨道名称自动发起付费请求。

`track:position` 上报任务、视频、位置、倍速、可见性和交互原因。普通时间更新最多每秒一次；跳转、播放、倍速和页面激活立即上报，广告期间不更新翻译位置。最近明确交互的页面拥有调度优先位置，其他页面的普通更新不会抢占它。导航后用视图代次、视频与任务编号过滤迟到结果；播放器更换时清理旧事件监听。

并发池按视频归属，每视频最多 3 个实际在途翻译请求。同视频不同任务共用名额；两个视频可以合计 6 个。第一段按最多 30 秒/600 字符分段，随后启动或缓冲不足时按最多 60 秒源时间或 1,200 个源字符分段，常规片段最多 180 秒或 6,000 字符，缓冲充足时最多 300 秒。边界保留完整字幕条目，已发送成员固定，已保存或已占用条目不重复规划。

连续缓冲在第一个未翻译 cue 处截止，已知无字幕区间不视为缺译；除以播放倍速得到实际观看余量。调度结合近期请求耗时优先当前位置和后续缓冲，然后补齐剩余全轨。跳转不取消在途请求，也不额外开第四个；下一空闲名额优先新位置，旧响应仍可保存。网络请求名额在 API 返回后释放，持久化与等待重试不占名额。

`track:status` 对所有任务状态返回完整源 cue、已保存译文、真实计数和 `revision`，并提供重试数量、在途数量、恢复能力与指标。播放器每 700ms 查询状态，只在已有有效译文的当前 cue 上显示双语并隐藏原生 CC；无译文时恢复原生 CC。整轨处于翻译、失败、暂停或取消状态，都不妨碍显示已保存 cue。

## 错误、保存与恢复

可恢复的网络、超时、429、临时服务和响应校验错误，首次请求后最多额外重试 2 次；退避 2 秒、8 秒并添加最多约 0.5 秒随机延迟，遵守服务端更长的等待要求。每次重发重新取得该视频名额。明确长度错误仅拆分失败片段，最小边界为单条字幕；错误凭据等配置问题暂停任务，用户取消不自动重试。重试耗尽保留缺口，其他片段继续。

成功响应先按源 ID 校验本段完整性，再与已保存结果合并并持久化。只有写入成功才公开新增译文，乱序返回不覆盖其他段。存储失败保留内存有效结果并重试写入，不重复请求 API；持续失败则暂停。单任务写入串行化，持久结果不保存 API Key。

错误详情仅进入控制台；后台记录视频、片段范围、尝试次数、错误类别、HTTP 状态、耗时与下一动作，不输出原始提供方响应或完整字幕。页面不弹窗、不自动打开错误面板，仅显示中性状态及恢复入口。设置字段的本地校验仍可提示输入问题。Firefox 的扩展后台 Console 可从 `about:debugging#/runtime/this-firefox` 中该扩展的「检查」入口打开。

Firefox MV2 持久后台拥有翻译任务，关闭标签页、导航或关闭字幕显示只解绑视图。浏览器完全退出时无法继续执行；下次启动只恢复记录，把未完成任务置为 `paused`，不自动调用 API。`track:resume` 在核对当前翻译配置后，只补缺失条目；从视频重新开启则通过 `track:start` 核对完整源指纹。明确重新翻译使用 `force: true`。旧版本完整缓存仍可读取，不能因升级重新收费。

任务 `complete` 必须覆盖每个源条目并成功保存。原文 SRT 只依赖已保存完整源时间轴；译文和双语 SRT 仅允许完整任务导出。三种文件均保持源顺序、时间戳及条目数，后台生成本地 Blob，再调用 Firefox downloads API。

## 验证边界

2026-10-10 的本轮检查包含 90 项自动化测试，以及 Firefox 157.0.1 上 42 项生产包与模拟 API 集成检查。集成已验证首段先显示、两视频六请求、跳转不取消、两次额外重试、页面不暴露错误详情、部分记录重启与仅补缺失、三种 SRT 实际下载；本地报告为 `output/firefox/buffered-segments/report.json`。

首批 20 秒是实际 API 的性能目标，不是分段覆盖时长。模拟服务通过只证明受控条件下的行为；0.3.0 已验证两个真实视频的完整保存、三种 SRT 及各三次冷启动；长视频实际首屏为 20.188–22.734 秒，20 秒目标尚未稳定达到。范围就绪与首次上屏分别记录，音乐视频源轨道第一条字幕从 31.945 秒才开始。详见 [验证记录](validation-0.3.md)。历史版本文档保留原始结果，不改写为本次实现证据。
