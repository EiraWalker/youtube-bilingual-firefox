# 文件与调用边界

本文描述 0.4.0。整轨获取源时间轴；翻译只服务有效观看需求，成功片段先进入内存，用户点击“缓存字幕”才落盘。

```text
YouTube → page-bridge → content（时间轴、播放状态、页面会话）
                     → background（观看租约、窗口、每视频并发）→ Chat Completions API
                     ← 已校验条目 ← 内存合并

“缓存字幕” → 后台快照 → Native Messaging 分块传输
                      → 已配置文件夹 / 稳定身份 / 当前完整修订
再次观看 → 源时间轴指纹匹配 → 目录回读 → 内存复用
设置页 → API 权限、缓存目录验证及定位、临时任务与旧版缓存
```

## 观看资格与调度

`track:start` 按视频、源语言及人工/自动来源、完整源内容与时间轴、接口、模型和目标语言计算身份；接口密钥不参与缓存身份。启动前先观察页面状态，配置和文件读取完成后只关联仍匹配的页面会话与视图。晚到的暂停、导航或隐藏状态能阻止异步启动发送首个请求。

`track:position` 携带页面会话、递增序号、视图、位置、倍速及 `active`。有效观看要求页面可见、视频实际播放、字幕开启、源轨道已核对且非广告。内容脚本对暂停、隐藏、关闭显示、结束、广告和离开立即上报；心跳每 2.5 秒更新，后台资格租约为 10 秒。标签页关闭或导航也会清理关联。旧序号和已退役页面会话不能抢回控制。

每个页面独立持有需求；同视频共享最多三个实际在途请求，不同视频独立。所有新增片段必须与某个有效需求的当前位置至前方 120 个源视频秒相交；边界条目保持完整。连续缓冲少于 60 秒时补充至上限，倍速只影响请求大小和提前量，不扩大窗口。没有字幕的空白不会拉入窗口之外的条目，也不会回绕补译已跳过的缺口。

暂停或离开不会中断已提交远程请求；已返回内容仍校验并合并内存。每次提交、重试或结果回调后补充都重新检查资格。重试等待不占并发槽，普通可恢复错误最多两次额外尝试；配置错误停止，明确长度错误只拆分被拒绝片段，用户取消会中断在途请求。

`paused` 表示没有有效观看需求，`buffered` 表示目前无需新增请求；两者均不代表整轨完成。`complete` 必须所有源条目具有有效译文。状态另外公开已缓存数量，不能以已翻译数量代替落盘数量。

## 字幕存续与主动缓存

默认源字幕、译文、任务及恢复记录不写扩展存储；显示只依赖内存条目。暂停、关闭显示及页面切换可在当前浏览器会话内复用，退出浏览器后不承诺保留。旧版内部缓存继续读取，新结果不会自动更新旧记录；显式清除操作仅删除旧版完整缓存。

`track:cache` 复制请求时已有条目，交给本地组件合并保存，不恢复播放、不开启字幕、不补译全片。快照之后到达的译文只保留内存，需要再次点击才落盘。目录未配置则进入设置，组件或目录不可用时保留临时译文。

缓存身份目录下 `current.json` 指向已完整生成的修订。修订包含结构数据、完整源 SRT，以及仅已有译文的部分或完整双语 SRT。写入新修订成功后原子切换指针；失败保持旧指针。组件合并旧有有效条目并保留较新修订的重叠译文，清理时只触及自身已知文件名，不递归删除用户目录。

传输限制为每块 96 KiB、每份结构数据 64 MiB，上传和下载均校验 SHA256。宿主校验缓存身份、条目、路径边界及软链接或 Junction，不能利用视频标题改变目录。只有扩展后台连接本地宿主，网页不能指定缓存目录、打开文件夹或执行任意命令。API Key 不进入公开配置、结构缓存、SRT 或日志。

冷启动只需要配置的目录与匹配源时间轴，不依赖扩展字幕索引。读取本身不发起翻译；后续补缺仍受有效观看窗口限制。更改目录不迁移或删除原目录文件。

完整 SRT 导出入口继续使用 Firefox downloads；部分双语文件由明确缓存操作生成并标识部分完成，不能冒充全轨导出。Windows 文件缓存需要随附本地组件，普通临时翻译不需要。

实现与验证见 [ADR 0004](decisions/0004-demand-driven-subtitles-and-explicit-cache.md) 和 [0.4.0 验证记录](validation-0.4.md)。历史全片后台翻译记录仅适用于对应旧版本。
