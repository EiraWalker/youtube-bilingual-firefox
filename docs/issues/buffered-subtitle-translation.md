## S1 首段译文完成即显示并保存

### What to build

让单个视频使用完整源轨道分段翻译，一个片段完成即可保存并用于双语显示。先消除「只有整轨完成才可公开译文」的内部限制，同时保留旧完整缓存与导出行为。此切片可先使用串行片段处理，交付从请求到保存、进度、播放器显示的完整流程。覆盖 US1、US7、US8。

### Acceptance criteria

- [ ] 获取一个完整源轨道，按连续字幕条目分段；开启时优先当前位置，正常路径不逐条请求。
- [ ] 单片段的全部目标条目通过校验并保存后立即可显示，无需等待整轨完成。
- [ ] 当前条目尚无译文时继续显示原文，视频不自动暂停；任务进度反映真实已完成条目。
- [ ] 片段乱序或重复结果按源条目标识安全合并，不更改时间戳；无效片段不能污染已保存结果。
- [ ] 既有完整任务仍可读取、显示和导出，设置兼容；源字幕获取行为保持可用。
- [ ] 自动化场景证明「第一段已保存和显示、下一段仍等待」，并验证异常结果不误标完整。

### Blocked by

None - can start immediately

## S2 每视频三个并发与自适应提前缓冲

### What to build

为视频提供三个在途翻译名额，以较小启动片段尽快取得译文，随后用较大片段提前翻译后续内容。根据实际请求耗时、字幕密度和播放倍速调整提前量，缓冲充足后继续完成整轨。首批 20 秒是需真实测量的目标。覆盖 US1、US2。

### Acceptance criteria

- [ ] 有足够未完成内容时能够同时发送三个请求，同视频所有任务合计始终不超过三个。
- [ ] 启动片段和常规片段均受时长、文本量限制；不截断字幕条目，采用 PRD 建议初值并记录实测调整。
- [ ] 连续缓冲在首个未翻译条目处截断，已知字幕空白不误判；倍速换算为实际观看时间。
- [ ] 优先当前位置及后续缓冲，缓冲充足时仍以较大片段完成剩余全轨；不重复请求已保存或在途内容。
- [ ] 记录源获取、排队、请求、保存及首批可用耗时；不能用已经播放过去的译文宣称达成首批目标。
- [ ] 可控延迟、字幕密度和倍速场景验证预取与并发；实际服务报告首批时间、覆盖率和请求数，未达 20 秒如实说明。

### Blocked by

- S1：首段译文完成即显示并保存。

## S3 跳转后优先补齐新位置

### What to build

将明确的播放位置变化传递给翻译调度，让空闲名额优先处理新位置及其后续内容。已发送请求等待远程返回并保存，不因跳转取消或额外复制请求。覆盖 US3。

### Acceptance criteria

- [ ] 三个名额占用时跳转不会发送第四个请求，也不会取消在途请求。
- [ ] 下一名额释放后优先处理最新位置缺口，若该范围已在途则复用，不重复提交。
- [ ] 旧位置的迟到结果仍能保存，当前页面按实际播放位置显示，不闪回旧位置字幕。
- [ ] 连续多次跳转优先最新明确交互；同视频后台页面周期性位置上报不抢走优先级。
- [ ] 已缓存范围跳转后直接使用；尚未翻译范围继续播放原文。
- [ ] 通过受控响应顺序验证跳转、缓存命中和连续跳转的完整显示与保存流程。

### Blocked by

- S2：每视频三个并发与自适应提前缓冲。

## S4 多视频独立并发并在后台完成

### What to build

让不同视频分别使用三个翻译名额。导航到新视频或关闭旧标签页后，旧视频继续补齐和保存，新页面只展示自己的结果。同视频相同翻译配置复用任务。覆盖 US4。

### Acceptance criteria

- [ ] A 视频三个请求尚未返回时，B 视频可以再发送三个请求；不存在全扩展三个名额的串行瓶颈。
- [ ] 关闭 A 标签页或切换到 B 后，A 仍继续处理剩余内容并保存；重新进入 A 可复用结果。
- [ ] 同视频、源轨道、目标语言和配置一致时多页面复用任务；不同轨道或配置结果互不污染。
- [ ] 同视频不同任务的并发总数仍不超过三个；不同视频独立推进。
- [ ] 明确取消 A 仅影响 A；关闭显示或离开页面不等同于取消任务。
- [ ] 受控端到端场景证明两视频可达六个在途请求、迟到响应不串字幕、关闭页面后任务仍完成。

### Blocked by

- S2：每视频三个并发与自适应提前缓冲。

## S5 翻译失败自动重试且仅控制台报错

### What to build

对可恢复的片段失败进行有限自动重试，成功片段不回退，其他片段继续处理。测试阶段只向控制台输出经过脱敏的错误与重试信息，不弹页面错误提示。采用 PRD 中标注为建议的错误分类与重试默认值。覆盖 US5、US6。

### Acceptance criteria

- [ ] 网络、限流、临时服务及可恢复响应校验错误最多自动重试两次，遵守退避和服务等待时间；总尝试次数清晰可查。
- [ ] 等待重试不占用在途名额，重发必须受每视频三个名额约束；失败不会造成无限循环或请求风暴。
- [ ] 明确长度错误仅拆分失败片段并有终止边界；无效凭据等配置错误暂停，用户取消后不再重试。
- [ ] 存储失败只重试保存已有有效结果；不重复调用翻译 API。成功片段始终保留。
- [ ] 重试耗尽保留缺口与恢复入口，其他片段可继续；不误标整轨完成，无译文区域继续显示原文。
- [ ] 页面无错误 toast、alert 或系统通知；控制台包含片段、尝试、类别与耗时，第三方消息也经过脱敏，不包含凭据或完整字幕。
- [ ] 注入暂时失败、永久失败、存储失败和取消，验证恢复结果、调用次数、并发和无弹窗行为。

### Blocked by

- S2：每视频三个并发与自适应提前缓冲。

## S6 恢复已保存片段并导出完整 SRT

### What to build

完成浏览器重启、重新观看和部分失败后的恢复流程：先展示匹配缓存，用户恢复时只补齐缺失部分；整轨完成后导出原文、译文或双语 SRT。兼容既有完整缓存，并验证跳转、多视频和重试共同作用时的数据完整性。覆盖 US7、US8。

### Acceptance criteria

- [ ] 浏览器重启后恢复已保存片段和任务状态，不自动发起付费翻译；用户再次开启或恢复时仅请求缺失部分。
- [ ] 视频、源轨道、内容指纹、目标语言及翻译配置不匹配时不能错误复用；兼容旧版本完整缓存。
- [ ] 原文 SRT 在完整源轨道就绪后可导出；译文和双语 SRT 必须等待全部条目有有效译文。
- [ ] 三种 SRT 的条目数量、顺序和时间戳与源时间轴一致，双语配对正确，不导出混合配置或缺失译文的完整文件。
- [ ] 跳转、多视频后台、自动重试与重启组合后，成功条目不丢失、不重复请求，未完成任务不误标完成。
- [ ] 两个回归视频各记录建议三次冷启动及缓存命中证据；报告真实首批耗时、并发、请求数和导出结果，环境阻塞与模拟通过分开记录。

### Blocked by

- S3：跳转后优先补齐新位置。
- S4：多视频独立并发并在后台完成。
- S5：翻译失败自动重试且仅控制台报错。
