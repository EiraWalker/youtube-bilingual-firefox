# 0.3.0 分段字幕翻译验证

日期：2026-10-10。六个任务对应 GitHub #1–#6。机器可读的脱敏摘要见 [validation-0.3.json](validation-0.3.json)。

## 已实现与验证

- 一次获取完整源轨道，首段校验并保存后即可双语显示；未翻译范围继续显示原生字幕，视频不暂停。
- 第一段最多 30 秒/600 字符，随后两个启动段最多 60 秒/1,200 字符；常规段 180 秒/6,000 字符，缓冲充足时 300 秒/6,000 字符。按字幕条目边界分段。
- 每视频三个真实在途请求，不同视频独立；跳转不取消请求，下一空闲名额处理新位置。匹配任务去重，关闭页面后后台继续。
- 临时失败额外自动重试两次；退避不占请求名额。配置错误暂停，长度错误有限拆分；日志只有脱敏控制台诊断，页面不显示错误详情或自动弹出面板。
- 片段串行合并保存，失败和取消保留已保存译文；保存失败仅重试存储。Firefox 重启不自动收费，重新开启或恢复后只补缺失。
- 保留旧完整缓存；原文、译文、双语 SRT 保持源时间轴，部分译文不能导出为完整文件。

Firefox 157.0.1 的隔离配置中，42 项端到端检查通过，真实请求峰值为 6。实际执行了播放器内显示、倍速、广告恢复、全屏、跳转、多标签后台、失败耗尽、部分缓存重启、恢复与三种文件下载；测试配置已清理。

本地详细证据：`E:\plugin\immersive-translate-local\output\firefox\buffered-segments\report.json` 及同目录截图。模拟服务的耗时不作为真实 API 性能证明。

长视频初始启动段上限为 60 秒/1,200 字符，首屏耗时 28.094 秒；根据该结果缩小第一段后进行了三次独立冷启动。完整源范围和后续翻译协议保持一致。

| uwS__WiOYTI | 31.000 秒 | 31.578 秒 | 33.235 秒 |

首屏指持续播放时当前位置的译文实际显示。冷启动探针取得有效保存结果后明确取消剩余任务，避免为了重复测量首批而反复翻译整个视频；完整任务校验单独进行。

音乐视频追加同钟测量确认：英语人工源轨道第一条字幕从 **31.945 秒**开始，开启时处于无字幕前奏。该次开启→首保存为 **14.868 秒**，开启→当前位置之后的首可用范围为 **20.180 秒**，首次上屏为 **31.346 秒**。因此约 31 秒上屏不能解释为 API 请求耗时。

长视频三次后台任务启动→范围就绪为 18.330、17.591、18.936 秒；它们不包含开启到任务创建的源获取阶段，不能代替端到端首批等待或宣称达到 20 秒。

**20 秒优化目标尚未稳定达到。** 功能链路已通过，远程模型耗时与源获取仍影响冷启动；后续优化应沿用统一浏览器时钟，分别测量源获取、远程返回、保存与上屏，不能通过缩短请求超时或排除源获取来改写结果。

真实证据位于 `output\firefox-live\buffered-real-*\live-probe.json`，九次探针均通过字幕链路校验并清理隔离配置。报告保留首次上屏和任务状态，不把模拟结果或后台耗时混入真实端到端统计。

## 构建与使用

安装包：`E:\plugin\immersive-translate-local\dist\youtube-bilingual-firefox-0.3.0.zip`。
`npm run package` 完成构建、Mozilla web-ext 校验和打包，零错误、零警告。该开发包仍采用 Firefox 临时加载方式，重新加载新版后刷新 YouTube 页面。

复现命令：`npm test`、`npm run package`、`python -X utf8 scripts/test-firefox.py`。
真实首批测量使用 `node scripts/test-firefox-real.mjs <video-id> <tag> --first-only --runs=3`，通过隐藏 stdin 提供配置；不传 `--first-only` 时校验完整保存及导出。

存储失败后尚未持久化的内存结果可能在浏览器退出时丢失。已持久化片段可复用，不能承诺存储故障/退出窗口中的零重复费用。
